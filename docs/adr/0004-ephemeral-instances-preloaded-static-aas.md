# ADR-0004: Ephemeral workpiece AAS, preloaded static AAS

- Status: accepted
- Date: 2026-10-03

## Context
Continuous production creates one workpiece-instance AAS roughly every 12 s. The user decided that instances are
ephemeral per factory session (D8).

## Decision
- The Postgres database of the `vf` compose stack lives on **tmpfs**. Every `docker compose up` starts with an empty DB.
- Static AAS (product type, machines, line, concept descriptions) are generated by the provisioner as AASX files into
  `infra/basyx/preload/` and imported by BaSyx Go at startup (`GENERAL_AAS_PRECONFIG_PATHS`).
- When the Godot simulation starts a new session (retained MQTT session message), the MES deletes all workpiece-instance
  AAS of the previous session.

## Consequences
+ Deterministic, clean state, and bounded DB size.
− No long-term traceability across sessions. Extension: archive instances as AASX before deletion.
